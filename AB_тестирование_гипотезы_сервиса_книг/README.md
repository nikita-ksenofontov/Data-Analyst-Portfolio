# Проект: проверка гипотез и A/B‑тестирование
---
## Часть 1. Проверка гипотезы: активность пользователей Книг в Москве и Санкт‑Петербурге

### Цель проекта
Проверить гипотезу о том, что пользователи из Санкт‑Петербурга в среднем проводят больше времени за чтением и прослушиванием книг в приложении, чем пользователи из Москвы.

### Исследуемые данные
Файл: `knigi_data.csv`  
Поля:
- `city` — город пользователя;
- `puid` — ID пользователя;
- `hours` — суммарное количество часов активности.

### Основные этапы исследования
1. Загрузка данных и первичный осмотр.
2. Удаление лишнего столбца `Unnamed: 0`.
3. Проверка на дубликаты.
4. Описательная статистика и отсечение выбросов (до 99‑го процентиля).
5. Выделение групп по городам и исключение пользователей, попавших в обе выборки.
6. Проверка статистической гипотезы с помощью t‑теста Уэлча для двух независимых выборок.

### Использованные библиотеки
- `pandas` — загрузка и обработка данных;
- `numpy` — численные операции;
- `scipy.stats` — t‑тест;
- `statsmodels` — расчёты мощности и эффектов;
- `matplotlib` — визуализация (не использовалась в финальных выводах, но подключена).

### Основные результаты анализа
- Размер выборки: 5 934 пользователя из Москвы, 2 288 — из Санкт‑Петербурга.
- Средние значения активности:
  - Москва: 8,09 часов;
  - Санкт‑Петербург: 8,44 часов.
- Результат t‑теста Уэлча: p‑value ≈ 0,239 (> 0,05).

### Выводы
Статистически значимых различий в средней активности пользователей Москвы и Санкт‑Петербурга не выявлено. Нулевая гипотеза не отвергается: нельзя утверждать, что жители Санкт‑Петербурга проводят больше времени в приложении.

## Часть 2. A/B‑тестирование нового интерфейса интернет‑магазина BitMotion Kit

### Цель проекта
Оценить, приводит ли упрощённый интерфейс сайта к росту конверсии в покупку среди новых пользователей. Проверить корректность проведения A/B‑теста и принять решение о развёртывании нового интерфейса.

### Исследуемые данные
1. `ab_test_participants.csv` — распределение пользователей по группам и тестам.
2. `ab_test_events.zip` — события пользователей (регистрация, просмотр страниц, покупка и т. д.).

Ключевые поля:
- `user_id` — идентификатор пользователя;
- `group` — группа теста (A — контрольная, B — тестовая);
- `event_name` — тип события;
- `event_dt` — дата и время события.

### Основные этапы исследования
1. Загрузка и очистка данных (удаление дубликатов).
2. Отбор пользователей, участвующих только в тесте `interface_eu_test`.
3. Проверка равномерности распределения пользователей по группам и отсутствия пересечений.
4. Фильтрация событий по горизонту анализа (первые 7 дней после регистрации).
5. Расчёт конверсии в покупку для каждой группы.
6. Оценка достаточности выборки по мощности теста.
7. Проверка гипотезы о росте конверсии с помощью Z‑теста для пропорций.

### Использованные библиотеки
- `pandas` — обработка и агрегация данных;
- `scipy` — статистические тесты;
- `statsmodels` — расчёт мощности и минимального детектируемого эффекта.

### Основные результаты анализа
- Распределение пользователей:
  - Группа A (контроль): 4 952 пользователя;
  - Группа B (тест): 5 011 пользователей.
  - Разница между группами: ≈1,19 % (в допустимых пределах).
- Конверсия в покупку за первые 7 дней:
  - Группа A: 27,81 % (1 377 покупателей);
  - Группа B: 29,54 % (1 480 покупателей).
- Абсолютный прирост: +1,73 п. п., относительный рост: +6,2 %.
- Z‑тест пропорций: p‑value ≈ 0,028 (< 0,05) — разница статистически значима.
- Расчёт мощности: необходимый размер выборки на группу — 3 761 человек; фактическая выборка достаточна.

### Выводы по результатам A/B‑тестирования
- Новый упрощённый интерфейс достоверно увеличивает конверсию в покупку в течение первой недели после регистрации.
- Эффект статистически значим при уровне значимости 5 %.
- Фактический прирост чуть ниже изначально запланированного MDE (3 п. п.), но остаётся коммерчески ощутимым.

### Рекомендации
- Развернуть новый интерфейс на всю аудиторию.
- Организовать мониторинг вторичных метрик (средний чек, удержание, длительность сессии) для контроля возможных побочных эффектов.
