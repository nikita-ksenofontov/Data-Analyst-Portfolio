# Анализ рынка жилой недвижимости Санкт‑Петербурга и Ленинградской области

## Визуализация результатов

Основной дашборд с метриками проекта доступен в Yandex DataLens:  
[📊 Дашборд проекта](https://datalens.yandex/ky41ai7lsyyc6)

## Цель проекта
Помочь агентству недвижимости из Петрозаводска спланировать выход на рынок Санкт‑Петербурга и Ленинградской области: определить перспективные сегменты жилой недвижимости и оптимальные сезоны для запуска маркетинговых кампаний и публикации объявлений.

## Задачи
- Изучить архив данных объявлений о продаже жилой недвижимости (схема `real_estate`).
- С помощью SQL‑запросов:
  - выявить наиболее привлекательные сегменты недвижимости по времени активности объявлений;
  - проанализировать сезонные тенденции на рынке (периоды повышенной активности продавцов и покупателей).
- Сформулировать выводы в виде краткой аналитической записки.
- Доработать существующий дашборд в DataLens, добавив новые аналитические элементы на основе полученных результатов.

## Описание данных
Данные взяты из архива сервиса Яндекс Недвижимость (объявления о продаже квартир в Санкт‑Петербурге и Ленинградской области за несколько лет), хранятся в схеме `real_estate`.

### Таблицы и ключевые поля

#### `advertisement` — информация об объявлениях
- `id` — идентификатор объявления (первичный ключ).
- `first_day_exposition` — дата подачи объявления.
- `days_exposition` — длительность нахождения объявления на сайте (в днях).
- `last_price` — стоимость квартиры в объявлении (руб.).

#### `flats` — характеристики квартир
- `id` — идентификатор квартиры (первичный ключ; связан с `id` в таблице `advertisement`).
- `city_id` — идентификатор города (внешний ключ к таблице `city`).
- `type_id` — идентификатор типа населённого пункта (внешний ключ к таблице `type`).
- `total_area` — общая площадь квартиры (кв. м).
- `rooms` — число комнат.
- `ceiling_height` — высота потолка (м).
- `floors_total` — этажность дома.
- `living_area` — жилая площадь (кв. м).
- `floor` — этаж квартиры.
- `is_apartment` — признак апартаментов (1 — да, 0 — нет).
- `open_plan` — признак открытой планировки (1 — есть, 0 — нет).
- `kitchen_area` — площадь кухни (кв. м).
- `balcony` — количество балконов.
- `airports_nearest` — расстояние до ближайшего аэропорта (м).
- `parks_around3000` — число парков в радиусе 3 км.
- `ponds_around3000` — число водоёмов в радиусе 3 км.

#### `city` — справочник городов
- `city_id` — идентификатор населённого пункта (первичный ключ).
- `city` — название населённого пункта.

#### `type` — справочник типов населённых пунктов
- `type_id` — идентификатор типа (первичный ключ).
- `type` — название типа населённого пункта.

## Методология
1. **Знакомство с данными** — подключение через DBeaver, первичный анализ структуры и качества данных.
2. **SQL‑анализ** — формирование запросов для решения ad‑hoc задач:
   - сегментация по ключевым параметрам (город, количество комнат, площадь и др.) с оценкой средней длительности экспозиции как индикатора спроса;
   - анализ сезонности через агрегацию по месяцам/кварталам (количество новых объявлений, динамика средней цены, длительность экспозиции).
3. **Аналитическая записка** — краткие выводы по сегментам и сезонным трендам для формирования бизнес‑стратегии.
4. **Доработка дашборда в DataLens** — добавление визуализаций, отражающих ключевые метрики: распределение по сегментам, динамика активности, сезонность, средние цены и длительность экспозиции.

## Инструменты
- СУБД и SQL‑запросы (анализ данных).
- DBeaver (исследование структуры данных).
- DataLens (визуализация и доработка дашборда).
